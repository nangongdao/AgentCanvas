# AgentCanvas v1.0 Upgrade Guide

AgentCanvas 1.0 is the first production release with explicit horizontal
runtime semantics. Product version `1.0.0` is independent from the API contract
version, which is also currently `1.0.0` but changes under the compatibility
rules in `contracts/`.

## Choose the upgrade path

- New deployment: create empty PostgreSQL and application-data volumes, then
  follow the production Compose procedure below.
- Existing v0.x SQLite deployment: stop writers and complete the
  [SQLite to PostgreSQL migration](v1.0-sqlite-to-postgresql.md) before serving
  traffic from v1.0.
- Existing v1.x PostgreSQL deployment: use the rolling release procedure in
  [the operations runbook](operations-runbook.md#4-upgrade-and-rollback).

Do not point more than one API or worker at SQLite. Horizontal roles require
PostgreSQL, Redis, and `STARTUP_MIGRATIONS=false`.

## Prerequisites

- Docker Engine with Compose v2 and at least 8 GiB available memory.
- PostgreSQL 17 with pgvector. The bundled image is
  `pgvector/pgvector:0.8.6-pg17-bookworm`.
- Redis 5 or newer; the release CI and production Compose use Redis 7.
- A valid Fernet `SECRET_KEY`, independent long API tokens, and a strong
  PostgreSQL password in an operator-owned `.env.production`.
- A verified backup and a tested rollback target before any in-place upgrade.

## Build and deploy 1.0 from source

From the repository root:

```bash
cp .env.production.example .env.production
# Replace every placeholder and keep IMAGE_TAG=1.0.0 or an accepted commit SHA.
docker compose --env-file .env.production -f compose.prod.yml config --quiet
docker compose --env-file .env.production -f compose.prod.yml build
docker compose --env-file .env.production -f compose.prod.yml up -d --wait \
  --scale backend=2 --scale worker=2
curl --fail http://127.0.0.1:8080/readyz
```

## Deploy the tested registry images

Set `BACKEND_IMAGE` and `FRONTEND_IMAGE` in `.env.production` to the GHCR
repository paths and set `IMAGE_TAG` to either `1.0.0` or the full commit SHA.
Both tags identify the same CI-built image. Pull those images explicitly and
forbid Compose from building a local replacement under the registry tag:

```bash
docker compose --env-file .env.production -f compose.prod.yml config --quiet
docker compose --env-file .env.production -f compose.prod.yml pull --policy always backend frontend
docker compose --env-file .env.production -f compose.prod.yml up -d --no-build --wait \
  --scale backend=2 --scale worker=2
curl --fail http://127.0.0.1:8080/readyz
```

Do not run `docker compose build` on the registry path, and never deploy an
unpinned `latest` tag.

The one-shot `migrate` service owns Alembic changes. `bootstrap` runs only after
migration succeeds, then the API, workers, scheduler, and relay start. A
long-running process must never run release migrations.

## Acceptance checks

Before restoring traffic, require all of the following:

```bash
curl --fail http://127.0.0.1:8080/livez
curl --fail http://127.0.0.1:8080/readyz
docker compose --env-file .env.production -f compose.prod.yml ps
```

- `/api/meta` reports product version `1.0.0`, database `postgresql`, and the
  expected memory/vector backends.
- `/readyz` reports migration `0030_callback_activation_boundary`, a persistent PostgreSQL
  checkpointer, and pgvector availability.
- Exactly two API and two worker containers are running, plus one scheduler and
  one relay.
- Login, one known workflow execution, SSE completion, one RAG query, and any
  preserved `waiting_approval` resume successfully.
- A fresh backup restores into a different empty database and passes
  `app.services.restore_drill` before the release is accepted.

## Rollback

Application-only rollback may select the previous immutable image tag when no
new migration has run. Once the database has advanced, stop every writer and
restore the pre-upgrade archive into a new database and data volume; do not run
automatic Alembic downgrades against production data. Keep v0.x source data and
the old `SECRET_KEY` until the v1.0 restore, retrieval, and approval-resume drills
all pass.
